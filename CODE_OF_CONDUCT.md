# 🤝 Code of Conduct

## 📌 Our Commitment

This project is committed to providing a professional, respectful, inclusive, and collaborative environment for everyone who participates.

All contributors, visitors, reviewers, and community members are expected to interact constructively and respectfully while participating in project discussions, issues, pull requests, reviews, and other project-related activities.

---

## 🎯 Purpose

The goal of this Code of Conduct is to maintain a healthy development environment where people can:

- 💡 Share ideas and suggestions
- 🐛 Report bugs
- 🚀 Propose improvements
- 🔧 Contribute code
- 📚 Improve documentation
- 🔍 Review contributions
- 🤝 Collaborate professionally
- 🧠 Learn from technical discussions

Constructive technical feedback is encouraged when communicated respectfully and with the goal of improving the project.

---

## ✅ Expected Behaviour

Participants are expected to:

- Communicate professionally and respectfully
- Provide constructive and actionable feedback
- Respect different viewpoints and experiences
- Focus discussions on technical problems and solutions
- Accept constructive criticism professionally
- Help maintain a productive development environment
- Respect contributor time and effort
- Follow project contribution guidelines
- Avoid unnecessary conflicts or disruptive discussions
- Give appropriate credit for meaningful contributions

---

## 💻 Technical Discussions

Technical disagreement is normal and can improve software quality.

When discussing implementation decisions:

- Focus on the code, architecture, behaviour, or technical approach
- Explain reasoning with relevant technical context
- Suggest alternatives when identifying problems
- Prefer evidence, reproducible examples, or documentation
- Avoid personal criticism
- Keep discussions relevant to the project

For example, instead of:

```text
This implementation is bad.
```

Prefer:

```text
This implementation introduces duplicated logic.
Extracting the shared behaviour into a reusable function
could improve maintainability.
```

The objective of code review is to improve the software—not criticize the developer.

---

## 🚫 Unacceptable Behaviour

The following behaviour is not acceptable:

- Harassment or intimidation
- Discriminatory or derogatory comments
- Personal attacks or insults
- Threatening behaviour
- Deliberate disruption of technical discussions
- Repeated spam or irrelevant promotional content
- Publishing another person's private information without permission
- Malicious contributions
- Intentionally misleading bug reports
- Abusive comments in issues or pull requests
- Any behaviour that creates an unsafe or hostile environment

---

## 🐛 Issues and Bug Reports

Issues should remain focused on improving the project.

When creating an issue:

- Use a clear and descriptive title
- Explain the problem accurately
- Provide reproduction steps when applicable
- Include relevant browser or environment information
- Include screenshots or error messages when useful
- Avoid duplicate issues
- Keep discussions focused on resolving the problem

---

## 🔄 Pull Requests

Pull requests should follow the project's contribution standards.

Contributors should:

- Keep changes focused
- Explain the purpose of the change
- Follow existing coding conventions
- Test changes before submission
- Respond constructively to review feedback
- Avoid unrelated modifications
- Resolve review discussions professionally

For detailed contribution instructions, see:

```text
CONTRIBUTING.md
```

---

## 🔍 Code Review Standards

Reviewers should evaluate contributions based on technical quality, including:

- Correctness
- Readability
- Maintainability
- Performance
- Accessibility
- Security
- Responsive behaviour
- Browser compatibility
- Code consistency
- Project architecture

Feedback should explain both the issue and, where practical, a path toward improvement.

---

## 🔐 Privacy and Security

Participants must not intentionally publish sensitive or private information.

Do not expose:

```text
Passwords
API keys
Access tokens
Private keys
Environment secrets
Authentication credentials
Personal private information
```

Potential security vulnerabilities should not be publicly disclosed when doing so could create unnecessary risk.

Follow the responsible disclosure process documented in:

```text
SECURITY.md
```

---

## 🛡️ Project Integrity

Contributors must not intentionally introduce:

- Malicious code
- Backdoors
- Credential-stealing functionality
- Destructive scripts
- Hidden tracking mechanisms
- Known security vulnerabilities
- Unauthorized third-party content

Contributions should support the legitimate goals of the project.

---

## ⚖️ Enforcement

Project maintainers are responsible for clarifying and enforcing these standards.

Depending on the severity and context of inappropriate behaviour, maintainers may:

1. Provide a private or public warning
2. Remove inappropriate comments or content
3. Close or reject an issue or pull request
4. Restrict further participation
5. Block a participant from the repository when necessary

Enforcement decisions should be proportionate, consistent, and focused on maintaining a professional project environment.

---

## 🌐 Scope

This Code of Conduct applies to project spaces including:

- Repository discussions
- Issues
- Pull requests
- Code reviews
- Documentation contributions
- Other official project collaboration channels

It may also apply when an individual is officially representing the project in another public environment.
